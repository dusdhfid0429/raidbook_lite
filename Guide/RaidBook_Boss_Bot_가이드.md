# 👹 LinC 보스 봇 가이드

> **파일**: `RaidBook_boss_Bot.py`
> **Config**: `Config/boss_config.json`
> **데이터**: `Data/RaidBook_Boss_Data.xlsx`
> **활성 메시지**: `Data/active_messages.json`
> **유저 매핑**: `Data/user_mapping.json`
> **백업**: `Data/Backup/`
> **로그**: `Log/RaidBook_boss_Bot_YYYY-MM-DD.log`

## 📋 개요

보스 출현 알림을 자동으로 보내고, 참석자 버튼 클릭으로 참석을 기록하는 봇입니다.

핵심 목적:
1. **알람 등록** — config 또는 명령어로 여러 보스 레이드 알람을 등록/관리
2. **참석자 수집** — 알람 메시지의 참석/취소 버튼으로 실시간 참석자 수집
3. **데이터 정리** — 보스별 참석자 데이터를 Excel 로 자동 수집, 통계, 정리

동작 흐름:
```
config 등록 → 봇 시작 시 자동 스케줄링 → 보스 20분 전 알림
→ 참석/취소 버튼으로 수집 → `close_minutes` 설정 시 자동 마감 / 미설정 시 무기한 유지 → Excel 저장
→ 매일 지정 시각에 데이터 정리 및 통계 갱신
```

## 🔌 채널 구성

| 채널 | 역할 |
|------|------|
| **알림 채널** (`alert_channel_id`) | 보스 출현 알림 embed + 참석/취소/획득 아이템 버튼 |
| **명령어 채널** (`command_channel_id`) | 명령어 입력 + 봇 시작/종료 알림 + 재시작 복구 결과 + 일일 정리 알림 + Excel 파일 업로드. 생략 시 알림 채널과 동일 |
| **득템 채널** (`loot_channel_id`) | 획득 아이템 공지 게시/수정. 보스 알림 메시지로 점프하는 하이퍼링크 포함. 생략 시 명령어 채널과 동일 |
| **`loot_force_user_ids`** | 참석자가 아니어도 **획득 아이템 버튼 사용 허용**할 UID 목록 (관리자/대리 입력자 등). 비어 있으면 기존 동작과 동일. alias 적용해 부계정/동명이인 UID도 자동 매칭 |

## ⚙️ Config (`Config/boss_config.json`)

```json
{
  "token": "봇 토큰",
  "base_dir": "C:\\Users\\사용자\\Desktop\\RaidBook_Bot",
  "alert_channel_id": 알림채널ID,
  "command_channel_id": 명령어채널ID,
  "loot_channel_id": 득템채널ID,
  "loot_force_user_ids": ["350663979875696651"],
  "daily_refresh_hour": 0,
  "daily_refresh_minute": 0,
  "close_minutes": null,
  "image_display": "banner",
  "image_canvas_size": [960, 540],
  "bosses": {
    "카스파": {
      "interval_hours": 2,
      "start_hour": 17,
      "start_minute": 0,
      "image": "Images/boss/카스파.png"
    },
    "드래곤": {
      "interval_hours": 4,
      "start_hour": 19,
      "start_minute": 30,
      "image": "Images/boss/드래곤.png"
    }
  }
}
```

| 항목 | 설명 |
|------|------|
| `token` | Discord 봇 토큰 |
| `base_dir` | 봇 루트 경로 (생략 시 스크립트 위치) |
| `alert_channel_id` | 알림 채널 ID |
| `command_channel_id` | 명령어 채널 ID (생략 시 알림 채널) |
| `loot_channel_id` | 득템 공지 채널 ID (생략 시 명령어 채널) |
| `loot_force_user_ids` | 참석 여부와 무관하게 획득 아이템 버튼 사용을 허용할 UID 목록 (alias 자동 적용) |
| `daily_refresh_hour/minute` | 일일 정리 실행 시각 (기본 00:00) |
| `close_minutes` | **보스 리젠 시각 기준** 자동 마감까지의 분(min). 예: `20` → 보스 출현 후 20분 마감, `0` → 출현 정각 마감. **`null` / 항목 제거 / 음수 시 자동 마감 비활성화 (알림 무기한 유지)**. 마감 비활성화 상태에서는 embed의 마감 카운트다운도 표시되지 않음 |
| `image_display` | 이미지 표시 방식. `banner`=embed 하단 큰 이미지, `thumbnail`=우측 작은 이미지, `both`=둘 다 표시 |
| `image_canvas_size` | Discord 업로드 전 이미지를 고정 투명 PNG 캔버스로 정규화할 크기. 기본 `[960, 540]` |
| `bosses` | 보스별 설정 (`interval_hours`, `start_hour`, `start_minute`) |
| `point_panel_channel_id` | 포인트 버튼 패널(`!포인트패널`)을 게시할 채널 ID. 그 채널엔 버튼 임베드만 두고 결과는 누른 사람만 보이는 ephemeral |
| `point_ranking_channel_ids` | `command_channel` 외에 `!pt`(포인트순위) 명령을 추가 허용할 채널 ID 목록 |
| `tts_register_announcement` | 보스 알림 등록 시 TTS 음성 알림 전송 여부 (기본 `true`) |
| `tts_regen_warning` | 리젠 5분 전 TTS 음성 알림 전송 여부 (보스봇 기본 `true`) |
| `tts_messages` | TTS 문구 템플릿. 키: `register`/`regen_warning`/`party_confirm`. `{boss_name}`/`{boss_time}` placeholder 사용 |

> 보스를 추가하려면 `bosses` 에 항목 추가. 각 보스의 `image`는 생략 가능하며, 기존 단일 보스 config (`boss_name`, `boss_interval_hours` 등) 도 하위 호환됨.
> TTS 음성 알림은 TTS 봇의 `default_voice_channel_id`가 설정돼 있어야 동작합니다.

## 🖼️ 보스 이미지 표시

`boss_config.json`의 `bosses` 또는 `daily_bosses` 각 보스 항목에 `"image"` 경로를 추가하면 알림 embed에 이미지가 표시됩니다. 파일이 없거나 읽을 수 없으면 이미지만 생략하고 메시지는 정상 전송됩니다.

이미지 표시 방식:

| 값 | 동작 |
|---|---|
| `banner` | embed 하단에 큰 이미지로 표시 |
| `thumbnail` | embed 우측 작은 이미지로 표시 |
| `both` | 하단 이미지와 우측 썸네일 둘 다 표시 |

원본 이미지 크기가 제각각이어도 `RaidBook_images.py`가 Discord 전송 전에 투명 PNG 캔버스로 정규화합니다. 기본 캔버스는 16:9 `[960, 540]`이며, 원본 파일 자체는 수정하지 않습니다.

`!sync`, 자동 마감, 참석/취소 버튼으로 embed를 수정하는 경우에도 config 이미지를 새 첨부 파일로 다시 업로드합니다. 그래서 기존 `attachment://...` 참조가 끊겨 이미지가 사라지는 현상을 방지합니다.

이미지가 있는 알림도 Discord 목록/푸시에서 `이미지 보냄`만 보이지 않도록, 메시지 본문에 짧은 제목이 함께 들어갑니다. 예: `📢 네크로맨서 보스 알림 | 리젠 17:00`. 마감으로 edit되면 현재 리젠 시간이 아니라 다음 타임을 계산해 `📢 네크로맨서 보스 마감 | 다음 리젠 19:00`처럼 표시합니다.

## 💬 명령어

### 알람 등록/관리

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `!startboss [보스명] [시각] [주기h]` | 보스 반복 알림 시작 (주기 생략 시 config 또는 2h) | `!startboss 카스파 13:00` |
| `!stopboss [보스명]` | 특정 보스 알림 중지 | `!stopboss 카스파` |
| `!stopboss` | 모든 보스 알림 중지 | `!stopboss` |
| `!setboss [보스명] [주기h]` | 실행 중인 보스의 출현 주기 변경 | `!setboss 카스파 3` |
| `!listboss` | 현재 등록된 보스 목록 | `!listboss` |

> `시각`: `HH:MM` 형식. 이미 지난 시간을 입력하면 주기 기준 다음 알림 시간을 자동 계산.

### 수동 알림 생성

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `!create [보스명] [시각] [분]` | 수동 알림 생성 (기본 20분) | `!create 발탄 20:00 30` |
| `!test [보스명]` | 테스트 알림 (2분 후 자동 마감) | `!test 카스파` |

### 참석자 수동 편집

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `!add [보스ID 또는 보스명+시각] [닉네임...]` | 특정 메시지에 참석자 수동 추가 (Excel + JSON 동시 반영) | `!add 카스파 26052620 짐보 와인` |
| `!remove [보스ID 또는 보스명+시각] [닉네임...]` | 참석자 수동 제거 | `!remove 1505112567712972881 짐보` |

> 보스 메시지는 **메시지 ID** 또는 **보스명 + YYMMDDHH(시각)** 두 형식 모두 지원.

### 참석 메시지 관리

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `!close [메시지ID]` | 참석 마감 (로그 검증 → Excel 저장) | `!close 1234567890` |
| `!activate [메시지ID] [분]` | 마감된 메시지 재활성화 (분 생략 시 무기한) | `!activate 1234567890 30` |
| `!extend [메시지ID] [분]` | 마감 시간 연장 | `!extend 1234567890 10` |
| `!reopen [YYMMDDHHMM] [분]` | 날짜+보스리젠시간으로 재활성화 (기본 20분) | `!reopen 2605161700 30` |
| `!delete [메시지ID]` | 메시지 삭제 (활성이면 JSON 에서도 제거) | `!delete 1234567890` |
| `!rename [이전] [새이름]` | 보스명 일괄 변경 | `!rename 발탄 발탄하드` |

### 데이터 복구 및 동기화

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `!recover [메시지ID]` | 마감된 메시지에서 참석자 → Excel 수동 복구 | `!recover 1234567890` |
| `!sync [메시지ID]` | Excel/config 기준으로 디스코드 embed와 이미지 업데이트 (⚠️ 버튼 모두 제거됨, 획득 아이템 버튼 다시 부착하려면 `!attachloot` 사용) | `!sync 1234567890` |
| `!attachloot [메시지ID 또는 all] [일수]` | **획득 아이템 버튼이 없는 기존 메시지에 버튼 부착**. `all` 모드는 알림 채널 최근 N일 메시지 일괄 스캔(기본 7일). 마감된 메시지는 획득 아이템 버튼만 활성화됨 | `!attachloot all 30` / `!attachloot 1234567890` |
| `!fixid` | ID 없는 데이터에 자동 ID 발급 | `!fixid` |
| `!fixnames [채널ID] [건수]` | 채널의 봇 메시지 embed에서 UID 숫자를 user_mapping 이름으로 일괄 교체 (기본 200건) | `!fixnames 0 100` |
| `!fixmsg [메시지ID...]` | 특정 메시지의 embed UID를 이름으로 교체 (공백으로 여러 개) | `!fixmsg 1506984905509441540` |
| `!migrate [보스명]` | 기존 5컬럼 → 새 6컬럼(UID/이름 분리) 마이그레이션 | `!migrate 카스파` |

### 조회 및 관리

| 명령어 | 설명 |
|--------|------|
| `!history [일수]` | 최근 N일 참석 히스토리 (기본 7) |
| `!stats [일수\|all] [상위N\|all]` | 참석자별 누적 통계 — 인원 순위 + 각자의 최다 참석 보스 Top 3. alias 통합 적용. 기본 30일/25명. `all` 입력 시 제한 해제(전원/전체 기간), 페이지 자동 분할 | `!stats 30 25` / `!stats all all` |
| `!포인트순위` (별칭: `!pt`, `!points`) | 전주 + 이번 주 합산 포인트 순위 (보스 + 전투봇 통합). 주차 기준: 월요일 18:00 초기화 |
| `!포인트기간 [기간]` (별칭: `!기간포인트`, `!ptrange`) | **지정 기간**의 멤버별 누적 포인트 순위. 기간: `today`·`week`·`month`·`2026-06`·`2026-06-01~2026-06-21`·`~2026-06-21`(처음부터)·`2026-06-01~`(오늘까지)·`all`(전체) |
| `!포인트패널` (별칭: `!pointpanel`) | `point_panel_channel_id` 채널에 포인트 버튼 패널 게시. 버튼 클릭 시 본인 등수/전체 순위를 ephemeral로 표시 (본인 줄 강조) |
| `!refresh` | Excel 서식 전체 재적용 + ID 자동 발급 |
| `!save` | Excel 채널 업로드 |
| `!setrefresh HH:MM` | 일일 자동 정리 시각 변경 (즉시 적용) |
| `!restart [silent]` | 백업 → ID 발급 → 서식 재적용 → 통계 갱신 → 저장 → 재시작. `silent`/`quiet`/`s` 입력 시 디스코드 알림 생략 |
| `!settle [메시지ID]` | 해당 보스 메시지에 대한 정산 패널을 회계봇에 트리거 (IPC `_settle_trigger`). 이미 정산된 보스는 회계봇이 기존 정산을 자동 인식. 같은 정산ID의 판매금액 입력 대기 패널이 있으면 새 메시지 대신 기존 패널을 수정. 정산 패널은 `accountant_config.json`의 **`settlement_channel_id`** 채널에 게시됨 | `!settle 1507045303596093500` |

### 멤버 관리

| 명령어 | 설명 |
|--------|------|
| `!collectmembers` | 서버 전체 멤버의 디스코드 UID → 닉네임 매핑을 `user_mapping.json` 에 수집/갱신 |

> `!collectmembers` 는 관리자가 일회성 또는 멤버 변동 시 실행. 수집된 UID 매핑은 회계봇 정산 결과 embed 에서 이름 표시에도 공유됩니다.

## 🔁 알람 동작 흐름

```
1. 보스 출현 20분 전
   - 알림 채널에 참석/취소 버튼 포함 embed 전송
   - active_messages.json 에 활성 메시지 등록

2. 참석/취소 버튼 클릭
   - 메모리 + active_messages.json 에 참석자 즉시 반영
   - embed 실시간 업데이트 (현재 참석자 표시)
   - 클릭한 본인에게만 ephemeral 안내 메시지 표시
   - Excel 에는 아직 저장하지 않음 (마감 시 일괄 저장)

3. 자동 마감 (config `close_minutes` 0 이상 시)
   - 보스 리젠 시각 + `close_minutes` 분 후 마감 (예: 20 → 보스 출현 후 20분, 0 → 출현 정각)
   - `close_minutes`이 null/항목 없음/음수 → **자동 마감 비활성화**, 알림이 무기한 유지됨
   - 마감 시: 로그 기반 참석자 검증 (로그 비면 JSON 신뢰, Excel 기존 데이터는 자동 축소하지 않음)
   - 버튼 제거, 최종 참석자 표시
   - 검증된 참석자 목록을 Excel 에 일괄 저장 + 백업 생성
   - active_messages.json 에서 메시지 제거

4. 다음 보스 알림 자동 스케줄링 (설정 주기)

5. 봇 시작 시
   - 활성 메시지 auto_disable 타이머 복구
   - config 보스 자동 스케줄링

6. 봇 종료 시
   - 모든 활성 알람 메시지 즉시 마감 + Excel 저장
   - active_messages.json 정리
   - 명령어 채널에 종료 알림
```

## 🎁 획득 아이템 기록

각 보스 알림 메시지에 **`획득 아이템` 버튼**이 추가되어 있습니다.

### 동작 흐름
1. 보스 참석자 또는 `loot_force_user_ids` 허용 사용자가 버튼 클릭 → 아이템 개수 선택 후 모달 노출 (모달에 **획득자 입력칸**, 쉼표 구분, 선택)
   - Discord 모달 5칸 제한 때문에 개별입력 모드 아이템은 최대 4개, 5개 이상은 "기타(직접입력)" 모드 사용
2. 모달 제출 시 — 아직 활성 메시지인 경우:
   - **(1단계) 참석자 보존**: 현재 참석자 목록을 로그 기준으로 검증 후 Excel 저장
   - **(2단계) 아이템 저장**: Excel `획득 아이템` 시트에 upsert(획득자 별도 컬럼 포함) + 보스 알림 embed 하단에 `🎁 획득 아이템: ...` + 획득자 입력 시 `👤 획득자: ...` 갱신
   - **(3단계) 득템 채널 공지**: **득템 채널** (`loot_channel_id`) 에 공지 게시 — 보스명, 시간, 획득 아이템, **알림 메시지로 이동하는 하이퍼링크** 포함
   - **(4단계) 회계봇 정산 트리거**: Excel 저장 성공 + 실제 아이템 변경이 있을 때만 IPC 를 통해 회계봇에 정산 시작 신호 전송
3. 이미 마감된 메시지에서 버튼 클릭 시: embed 만 갱신 + 득템 채널 공지 수정
4. 버튼 재클릭 시 기존 기록이 모달에 prefill 되어 **수정 가능**
5. 수정 시 득템 채널 공지도 함께 update (보스 알림 메시지 ID 가 유니크 키)
6. 같은 보스 메시지에서 한 명이 아이템 저장/득템 공지/정산 패널 갱신을 처리 중이면 다른 사용자의 버튼 클릭 또는 모달 제출은 해당 사용자에게만 `잠시 후 다시 시도` 안내
7. 처리 시작 전에 열려 있던 오래된 모달은 저장하지 않고 다시 시도 안내
8. 동일 내용이 중복 제출되면 `정산 트리거 생략` 로그만 남기고 정산 패널을 새로 만들지 않음
9. **마감 후에도** 획득 아이템 버튼은 활성. 보스 잡고 나서 여유롭게 입력 가능

### 득템 채널 공지 동기화
- 유니크 키: 보스 알림 메시지 ID
- 최초 등록 시 생성된 득템 채널 공지 메시지 ID를 Excel `득템 메시지 ID`와 활성 알림 상태(`active_messages.json`)에 함께 저장
- 이미 등록된 보탐이면 → 알림 상태의 공지 ID → Excel의 공지 ID → 보스 알림 링크 검색 순서로 기존 공지 메시지를 찾아 edit
- 등록 안 된 보탐이면 → 새 공지 메시지 send
- 매핑(보스 메시지 ID ↔ 공지 메시지 ID)은 Excel `획득 아이템` 시트의 `득템 메시지 ID` 컬럼에 보존
- 기존 아이템 수정 중 저장된 공지 ID의 메시지가 삭제됐거나 권한 문제로 접근할 수 없으면 중복 방지를 위해 새 공지는 만들지 않고 경고만 표시
- 최초 등록 공지 메시지가 생성되면 ID 매핑을 즉시 갱신
- Excel 저장 실패 시 득템 공지는 시도될 수 있으나 회계봇 정산 자동 트리거는 보류

### 강제 허용 (`loot_force_user_ids`)
- 참석자가 아니어도 획득 아이템 버튼 사용 가능한 UID 목록
- alias 시스템과 결합 — 부계정/동명이인 UID 어느 쪽으로 등록해도 canonical UID 매칭
- 강제 허용으로 통과한 경우 로그:
  ```
  [loot 강제허용] 명가_짐보(350663979875696651) → 보스 카스파 21:00 1506984905509441540
  ```

## 🏆 포인트 시스템

보스/전투 참석 시 자동으로 포인트를 부여합니다. `!포인트순위`(별칭 `!pt`, `!points`) 명령어로 합산 순위를 조회할 수 있습니다.

- `!pt`는 기본적으로 `command_channel`에서만 동작하며, `point_ranking_channel_ids`에 등록한 채널에서도 추가 허용할 수 있습니다.

### 포인트 버튼 패널 (`!포인트패널`)

`command_channel`에서 `!포인트패널`(별칭 `!pointpanel`)을 실행하면 `point_panel_channel_id` 채널에 **버튼 임베드**를 게시합니다.

- 멤버가 버튼을 누르면 **누른 본인에게만 보이는(ephemeral)** 메시지로:
  - 상단: 본인 등수/점수 (`N명 중 K등 · P점`)
  - 하단: 전체 순위. 본인 줄은 `📍 굵게 + ⬅ 나` 마커로 강조 (데스크톱·모바일 모두 호환)
- 영속 버튼(custom_id)이라 봇 재시작 후에도 동작
- 패널 채널엔 결과가 쌓이지 않아 버튼 임베드만 유지됨
- 봇이 패널 채널에 **메시지 보내기 / 링크 임베드** 권한이 있어야 게시됩니다

### 포인트 계산 기준

| 조건 | 포인트 |
|------|--------|
| 커츠 / 도펠겐어 보스 | 2.0점 |
| 여왕개미 / 여왕거미 보스 | 1.5점 |
| 기타 보스 | 1.0점 |
| 취약시간 (03:00 ~ 09:59) | 2.0점 |

> 타입 포인트와 취약시간 포인트 중 **높은 값이 최종 점수**로 적용됩니다 (`max` 방식).  
> 예: 커츠 03:00 보스 → `max(2.0, 2.0)` = **2.0점**, 카스파 04:30 → `max(1.0, 2.0)` = **2.0점**

### 주차 기준

- 주차 초기화: **매주 월요일 18:00**
- `!포인트순위` 집계 범위: **전주 전체 + 이번 주 명령어 입력 시점까지** 합산

### Excel 저장

- 보스봇: `RaidBook_Boss_Data.xlsx` 날짜 탭 → `획득포인트` 컬럼 (7번째)
- 전투봇: `RaidBook_Combat_Data.xlsx` 날짜 탭 → `획득포인트` 컬럼 (8번째)
- 마감 시 자동 계산하여 저장

### 기존 데이터 소급 적용

`recalc_points.py` 스크립트로 기존 Excel 데이터에 포인트를 일괄 적용할 수 있습니다.

```bash
# 두 봇 모두 종료 후 실행
python recalc_points.py
```

- 이미 값이 있는 셀은 건드리지 않음 (재실행 안전)
- 실행 전 자동 백업 생성

## 🔄 alias 시스템 (`Data/uid_alias.json`)

같은 사람의 부계정 또는 동명이인 UID를 **canonical UID** 하나로 통합 처리. 보스/전투/회계 봇 모두 공유.

### 동작
- `!stats` 통계 집계 시 → 같은 사람의 여러 UID 행이 한 사람으로 합산
- `loot_button` 참석 검사 시 → canonical UID 기준 비교
- `loot_force_user_ids` 검사 시 → canonical UID 기준 비교

### 종류
| 분류 | 설명 | 예시 |
|---|---|---|
| `same_person` | 본계정 + 부계정 등 같은 사람의 여러 계정 | 명가_불 (`362845562849984513` + `1322928473525981256`) |
| `homonym` | 동명이인이지만 운영상 한 사람으로 처리 결정 | 명가_사군 / 명가_옵션 |

### 로그 형식
```
[alias] 1322928473525981256 → 362845562849984513 | same_person: 명가_불 부계정
[stats] alias 통합 적용: 16건 (동명이인/부계정 통합)
```

### `uid_alias.json` 구조
```json
{
  "_notes": {
    "1322928473525981256": "same_person: 명가_불 부계정 → 362845562849984513"
  },
  "1322928473525981256": "362845562849984513"
}
```

> **원본 Excel 데이터는 절대 수정하지 않습니다**. 통계/검사 시점에만 alias가 적용되므로 alias만 제거하면 원상 복귀 가능합니다.

## 📊 데이터 수집 및 정리

### 자동 수집
- 마감 시 참석자 데이터가 Excel 날짜별 탭에 저장됨
- 알람 생성 시점의 날짜 기준으로 시트에 저장 (23:40 알람 → 00:20 마감이어도 알람 생성일 시트에 저장)

### Excel 자동 마이그레이션
- 데이터 갱신 시점(`!refresh`, `!save`, `!restart`, `!fixid`, 일일정리) 에 자동 실행
- `RAW_HEADERS` 와 시트 헤더를 비교하여 불일치 시 컬럼 위치 자동 보정

### 누락 데이터 자동 복구 (일일 정리 1단계)
- Discord 채널에서 최근 7일 마감된 메시지를 스캔
- Excel 에 없는 메시지의 참석자를 embed 에서 파싱하여 자동 저장
- 채널 메시지가 삭제되어도 기존 Excel 데이터는 삭제하지 않음

### 로그 기반 데이터 검증 (일일 정리 2단계 + 마감 시)
- 최근 7일 로그 파일에서 참석/취소 이벤트 파싱
- 메시지 ID 로 정확한 매칭 (같은 보스명+시간이 반복되어도 구분)
- 이벤트 리플레이로 최종 참석자 리스트 구성
- Excel 데이터와 비교해 로그에만 있는 참석자는 누락분으로 추가
- Excel에 있지만 로그에 없는 참석자는 삭제하지 않고 `[로그 검증 보류]`로 기록
- 마감 시점에도 JSON vs 로그 비교 (로그 0건이면 JSON 신뢰)
- 구 형식 로그와 하위호환

### 일일 자동 정리 (매일 지정 시각, 기본 00:00)
- Excel 백업
- ID 없는 데이터에 자동 ID 발급
- 전체 시트 서식 재적용
- 히스토리 / 보스별 참석 현황 / 누적 통계 갱신
- 시트 순서 정리
- 명령어 채널에 완료 알림 + 갱신된 Excel 파일 전송

## 📊 Excel 구조 (`RaidBook_Boss_Data.xlsx`)

| 시트 순서 | 시트명 | 내용 |
|------|------|------|
| 1 | `누적 통계` | 참석자별 전체 누적 + 날짜별 참석 횟수 (히트맵) |
| 2 | `보스별 참석 현황` | 보스 알람별 참석자 체크 매트릭스 (✅/❌) |
| 3 | `획득 아이템` | 보스 메시지별 획득 아이템 (메시지 ID 기준 upsert) |
| 4 | `히스토리` | 날짜/보스명/시간/참석자 수/참석자 목록 |
| 5+ | `YYYY-MM-DD` | raw 참석 데이터 (최신순 정렬) |

### Raw 참석 컬럼

`메시지 ID` / `보스명` / `보스 출현 시간` / `참석자ID(uid)` / `참석 시각` / `참석자이름` / `획득포인트`

- `참석자ID(uid)`: 디스코드 사용자 고유 ID (snowflake). `user_mapping.json` 기반으로 자동 채움
- `참석자이름`: 서버 닉네임. `user_mapping.json` 에 없는 경우 디스코드 display_name 사용
- `획득포인트`: 해당 보스 참석 시 획득한 포인트 (보스 타입 + 취약시간 기준 자동 계산)

### 획득 아이템 컬럼

`메시지 ID` / `보스명` / `보스 출현 시간` / `획득 아이템` / `마지막 수정자` / `마지막 수정 시각` / `득템 메시지 ID` / `획득자`

- `메시지 ID`: 보스 알림 메시지 ID (유니크 키)
- `득템 메시지 ID`: 득템 채널에 게시된 공지 메시지 ID (수정 동기화용)
- `획득자`: 8번째 컬럼으로 추가됨 (기존 컬럼 안 밀림, 하위호환). 정산 아이템 집계에는 미반영

## 🔄 자동 기능 & 안전장치

- **보스 스케줄**: 등록된 보스를 설정한 주기로 자동 알림
- **자동 마감**: 알림 생성 후 설정 시간이 지나면 버튼 자동 비활성화
- **카운트다운 표시**: 알림 embed 의 `🔒 마감 in N minutes` 가 Discord 클라이언트에서 자동 갱신 (relative timestamp `<t:UNIX:R>` 사용, 봇 부하 없음). `!extend` 로 연장하면 즉시 갱신됨
- **마감 시 참석자 검증**: JSON ↔ 로그 양쪽에서 교차 확인. 로그 매칭 0건이면 JSON 신뢰
- **자동 저장 재시도**: 엑셀이 외부 앱에서 잠겨있을 때 0/1/2/4초 백오프로 최대 4회 재시도
- **자동 백업**: 저장 **성공 직후**에만 백업 생성 (최대 10개 보관, 손상 파일 백업 풀 오염 방지)
- **자동 복구**: 일일 정리/refresh 시 채널에 남아 있는 마감 메시지 중 Excel에 없는 데이터만 추가
- **이미지 재업로드**: `!sync`, 마감, 버튼 편집 시 config 이미지를 다시 첨부하여 embed 이미지 참조가 끊기지 않도록 처리
- **봇 재시작 시 active_messages.json 기반 메시지 버튼 + 마감 타이머 자동 복구**
- **봇 종료 시 활성 메시지 즉시 마감 + Excel 저장** (참석자 데이터 유실 방지)
- **날짜 경계(자정) 마감 시에도 알람 생성일 기준으로 올바른 시트에 저장**
- **Excel 저장 시 `message_id` + 참석자명 중복 체크**
- **모든 Excel 접근에 `excel_lock` 적용** (같은 프로세스 내 동시 실행 충돌 방지)
- **참석/취소 View Lock**: 여러 유저가 동시에 버튼을 눌러도 순차 처리

## ⚠️ 주의사항

- `alert_channel_id` 에 알림 메시지, `command_channel_id` 에서 명령어 입력
- 메시지 ID 는 디스코드에서 메시지 우클릭 → "ID 복사"로 확인
- `!delete` 는 디스코드 메시지를 삭제하며 활성이면 JSON 에서도 제거
- Discord 메시지가 수동 삭제되어도 Excel/백업의 기존 참석 데이터는 자동 삭제되지 않습니다. 단, `!sync`/`!recover`는 원본 Discord 메시지가 존재해야 동작합니다.
- **엑셀 파일을 열어둔 상태에서 마감되면** 자동 재시도(최대 4회) 후에도 실패 시 명령 채널에 `⚠️ 엑셀 저장 실패` 알림이 옵니다. 엑셀을 닫고 `!refresh` 를 실행하면 로그 기반으로 자동 복구됩니다.
- 참석/취소 이벤트는 항상 로그에 기록되므로, 마감 시 저장이 실패해도 `!refresh` 또는 `!recover [메시지ID]` 로 복원할 수 있습니다.

## 🛠️ 트러블슈팅 & 기존 데이터 마이그레이션

### 기존 5컬럼 Excel → 새 6컬럼(UID/이름 분리) 포맷
- 방법 1 (자동): `!refresh` 또는 `!save` 실행 → 자동 마이그레이션
- 방법 2 (수동): `!migrate 카스파` → 보스명 지정하여 수동 변환

> 신 포맷은 `메시지ID / 보스명 / 보스시간 / 참석자ID(uid) / 참석시각 / 참석자이름` (6컬럼). 이전 5컬럼 포맷(이름만)에서 자동 변환됩니다.

### 마감 시 참석자가 0명으로 처리됨
이전 버전에서 발생하던 버그입니다. 현재는 로그 매칭이 0건이면 JSON 데이터를 신뢰합니다.
이미 0명으로 마감된 데이터는 `!recover [메시지ID]` 로 수동 복구 가능.

### 획득 아이템 버튼이 안 보임
- 봇 업데이트 전 등록된 오래된 메시지는 버튼이 없을 수 있음
- `!attachloot all 30` 으로 최근 30일 메시지 일괄 부착 가능
- `!sync [메시지ID]` 는 embed와 이미지를 Excel/config 기준으로 갱신하면서 **모든 버튼을 제거**하므로, sync 후에는 `!attachloot [메시지ID]` 로 버튼을 다시 부착하세요.

### sync 후 이미지가 사라짐
현재 버전은 `!sync`, 마감, 참석/취소 편집 시 config의 `image`를 다시 읽어 새 첨부 파일로 업로드합니다. 이미지가 보이지 않으면 아래를 확인하세요.

- `boss_config.json`의 해당 보스 `image` 경로가 실제 파일과 일치하는지 확인
- `image_display`가 `banner`, `thumbnail`, `both` 중 하나인지 확인
- 봇에 해당 채널의 메시지 보기/메시지 기록 보기/메시지 보내기/파일 첨부 권한이 있는지 확인
